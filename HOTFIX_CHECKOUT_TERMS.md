Checkout hotfix rationale: the server correctly requires termsAccepted=true before creating an order/payment session. The two-step client was calling createOrder immediately on /checkout/payment while initialForm deliberately resets termsAccepted=false, causing the payment initialization request to fail before Stripe could mount. This hotfix waits for explicit policy acceptance on the Payment page, then creates the order/Stripe session. Edit/Back resets acceptance and the checkout token so changed information creates a fresh authoritative payment session.
