# WELCOME10 redemption implementation

Status: review-only, NOT deployed. A dedicated service-role RPC must lock the campaign row, paid order, and matching reservation in that order; verify the canonical paid order, email identity, first-paid-order policy, and absence of prior redemptions; insert one redemption, increment usage once, and mark the hold consumed in one transaction. Repeated calls must return success only when the matching redemption and consumed hold both exist. Expired or released holds require Stripe timestamp reconciliation rather than automatic consumption. The existing general-purpose coupon RPC must reject WELCOME10 or delegate to the hardened path. Guest email ownership must be verified server-side. Keep the feature disabled until isolated PostgreSQL concurrency tests, Stripe replay tests, and normal-coupon regression tests pass. No production SQL or webhook changes authorized.
